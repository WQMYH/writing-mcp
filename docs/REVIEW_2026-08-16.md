## 1. 审计发现的关键缺陷：AUD-021 源指纹复用失效 ✅（已独立验证，修复已提交 `2e07df2`）

> 复核结论：缺陷论断成立——修复前 `service.index()` 不记录指纹，`ensureFresh` 在 `previous === undefined` 时跳过增量更新，"rebuild → 编辑 → 首次 explore" 读取旧数据；修复后该路径实测可见新内容（见 §8）。

### 1.1 问题描述

`IMPLEMENTATION_STATUS.md` 和 v2 计划均声称 AUD-021（源指纹复用 store，未变化不重载）已完成（提交 `c376df7`），但 `tests/service-reuse.test.ts` 中的 **"source edit is picked up by the next explore"** 测试实际处于失败状态。

### 1.2 根因分析

`service.ts` 的 `ensureFresh()` 方法中存在逻辑缺陷：

```typescript
// service.ts ensureFresh() 原始代码
const previous = this.fingerprints.get(workRef);
this.fingerprints.set(workRef, fingerprint);
if (!this.stores.has(workRef)) { await this.indexUnlocked(workRef, "incremental"); return; }
if (previous === undefined || previous === fingerprint) return;  // ← 缺陷在此行
await this.indexUnlocked(workRef, "incremental");
```

**触发路径**：

1. `service.index("rebuild")` 执行成功，但**不记录源指纹**到 `this.fingerprints`
2. 文件被编辑后，`service.explore()` 调用 `ensureFresh()`
3. `ensureFresh` 中 `previous = this.fingerprints.get(workRef)` 返回 `undefined`
4. 条件 `previous === undefined` 为 true → **直接 return，跳过增量更新**
5. explore 在旧数据上搜索，新内容不可见

**本质**：`previous === undefined` 被错误地等同于"无需更新"，而实际含义是"从未记录指纹，无法判断是否需要更新"。

### 1.3 修复方案

在 `service.index()` 完成后记录源指纹：

```typescript
// 修复后
async index(workRef, mode) {
  return this.serial(workRef, async () => {
    const result = await this.indexUnlocked(workRef, mode);
    if (mode !== "status") {
      const candidate = this.works.get(workRef);
      if (candidate) this.fingerprints.set(workRef, await this.sourceFingerprint(candidate));
    }
    return result;
  });
}
```

修复后的流程：

1. `service.index("rebuild")` 完成 → 记录指纹 `fp_A`
2. 文件编辑 → 文件系统指纹变为 `fp_B`
3. `ensureFresh` → `previous = fp_A`，`fingerprint = fp_B`，`fp_A !== fp_B` → 触发增量更新
4. 增量索引检测到 chapter-01 的 semantic hash 变化 → 重新索引该文档
5. explore 在新数据上搜索 → 找到编辑内容

### 1.4 验证结果

- 修复前：54/55 通过，AUD-021 "source edit is picked up" 失败
- 修复后：55/55 全部通过

### 1.5 修改文件

- `packages/core/src/service.ts`：`index()` 方法，增加指纹记录（+1 行实质改动）
